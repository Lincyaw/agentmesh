A SMALL LAYER BETWEEN YOUR MACHINES

Independent sessions.
Shared reach.

Agentmesh runs one local daemon per machine. Each coding session connects through MCP, and the daemons exchange messages over iroh.

01 / LOCAL

One binary.
Your own mailbox.

Machine identity, inbox, and outbox stay in local SQLite. Each session gets its own address.

02 / CONNECTED

Direct when possible.
Relayed when needed.

iroh provides encrypted transport across networks. No central Agentmesh application server to run.

03 / PERSISTENT

A message can wait
for a machine.

The sender keeps an outbox and retries after outages. Replies retain their sender and conversation.

BEFORE YOU CONNECT

A few useful details.

Does the first machine need to stay online?

Only while redeeming its invitation. Members then synchronize membership and communicate directly. Any online member can create another invitation.

What happens when a machine is offline?

The message remains in the sender’s local outbox. Delivery resumes when both daemons are online. A relay provides transport, not an offline mailbox.

Do I need a different way to launch my CLI?

Keep using claude, tclaude, codex, and tcodex. Claude binds when MCP starts; Codex uses a SessionStart hook on the first turn. Native Codex reminders use its normal shared daemon, not a standalone stdio App Server or a --no-daemon session.

Will a message bypass an approval or inbound hold?

No. Explicit tool approval settings and Claude inbound holds remain effective. Such messages wait in the inbox until the harness allows processing. Agentmesh does not restart a stopped harness.

Which platforms are supported?

The implementation targets macOS and Linux with Unix sockets. Use the matching OS and architecture archive from Releases, or build from source with Rust 1.94 or newer.

What has actually been tested?

22 local regression checks cover independent iroh nodes, MCP, invitations, groups, recovery, and isolation. Real tclaude and official Codex models passed idle wake, reply, and acknowledgement checks. TCodex passed MCP and native binding checks; its configured model returned upstream HTTP 429 during model verification.
