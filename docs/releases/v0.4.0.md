# Agentmesh v0.4.0

Operate a remote workspace from a local Claude Code or Codex session over the existing
iroh connection. The server needs Agentmesh, without a model runtime.

- Publish workspace roots and explicitly grant individual machines read, write, and execute access.
- Discover and operate remote workspaces through nine MCP tools or the JSON CLI.
- Read, list, search and atomically replace bounded UTF-8 files without following symlinks.
- Submit asynchronous shell jobs with caller-scoped idempotent request IDs.
- Resume reading persisted, bounded stdout/stderr through UTF-8-safe byte cursors.
- Cancel jobs, enforce timeouts, revoke grants, and retain interrupted records after restart without replay.

Public relays, public node address discovery/publication, and public DNS fallback
resolvers are disabled. Configure an explicit self-hosted relay when needed across NAT.
An optional `--dns-server IP:port` selects a private DNS resolver. Peer tickets and
invitations cannot redirect the client to an unconfigured relay.

Run `agentmesh setup` with the new binary on both machines and reconnect existing MCP
sessions. Upgrade preserves mailbox state and the seven communication-tool grants;
remote tools retain normal harness approval policies. A v0.3 peer can still exchange
messages but must upgrade before accepting workspace requests.

Execute permission runs with the remote daemon account and is not an OS sandbox.
Native harness shell and file tools remain local. Native exec-server remapping,
interactive PTYs and port forwarding are outside this release.

Validation: 34 local regression checks, optimized build, formatting and Clippy passed;
